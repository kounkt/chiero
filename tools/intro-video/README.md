## 書き出し

```sh
sh tools/intro-video/build.sh                 # BGM合成 → 全コマ撮影 → MP4 → /media/ へ
node tools/intro-video/render.mjs --stills 8,30,55.5   # 指定した秒の静止画だけ（確認用）→ out/stills/
```

必要なもの: Node.js 18 以上、Python 3（numpy・scipy）、ffmpeg（無ければ `pip install imageio-ffmpeg` の同梱版を使う）、
Playwright の Chromium。初回は `build.sh` が `npm install`（GSAP・フォント・Playwright）を行う。
4並列で数分かかる。途中のコマは `out/`（git に入れない）に残る。

## 直すとき

- **文言・配置**: `composition.html` と `composition.css`
- **動きと時刻**: `timeline.js`（場面ごとに区切ってある）
- **場面の長さ**: `scenes.json`。映像と BGM の両方がこの表を読む
- **BGM・効果音**: `bgm.py`。効果音の時刻は `timeline.js` の動きに合わせて手で置いてあるので、
  動きの時刻を変えたら `bgm.py` の該当箇所（帽子の着地、章の扉、吹き出し、常世の点の減少など）も直す

## 設計の要点（なぜこうなっているか）

- **一本のタイムラインを1コマずつ進めて撮る**: 画面は HTML/CSS で組み、すべての動きを GSAP の一本の
  タイムラインに載せる。書き出しは `__frame(i)` で i/30 秒へ進めて撮るだけ。CSS の transition・animation と
  requestAnimationFrame は使わないので、何度撮っても同じ絵になる
- **常世は作品の正本をそのまま動かす**: `/tokoyo/kami.js` と `/tokoyo/works.js` を読み込み、サイトと同じ式・
  同じ描画・同じ速さ（一巡り5秒）で描く。写しを作らないので、作品を直せば動画も追従する。
  残像は前のコマに依存するため、並列で途中から撮る場合は場面の頭から残像を積み直す。
  60Hz の画面と同じ残像になるよう、1コマに2回描いている
- **常世の場面の赤は落款の一点だけ**: 作品の掟に合わせ、ヘッダーの赤い線とロゴをこの場面では隠す
- **BGM は数式から合成する**: 既存の楽曲や音素材を使わないので権利の確認が要らない。乱数の種を固定して
  いるので、何度作っても同じ音になる。ラウドネスは -16 LUFS 付近、ピークは -1 dBFS 以下
- **色は BT.709 で変換して書き込む**: ffmpeg の既定（BT.601）のままだと、再生時にブランドの赤がずれる
